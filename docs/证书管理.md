# 证书管理模块文档

> 最后更新：2026-07-15

## 概述

证书管理模块为游雁学院提供电子证书的全生命周期管理：模板管理 → 证书定义 → 颁发 → 学员查看/下载。

## 体系结构

```
12 套内置 PNG 模板（v1-v6 竖版 + h1-h6 横版）
   ↓
[前端] 可视化编辑器（拖拽 / 文字编辑 / 印章 / 背景）
   ↓
[Server] design 数据落库到 certificates[].design
   ↓
[颁发流程] issueCertificateInternal → 仅写 user_certificates 记录（**不生成 PNG**）
   ↓
[学员端 / 管理后台预览] 浏览器内用 html-to-image 即时渲染 PNG（imageUrl 缺失时自动回退）
```

## 后端 API

### GET /api/certificates/templates
返回 12 套模板的元数据，用于"模板选择"弹窗。
- **响应**：`{ success: true, data: [{ id, name, layout, thumbnail, style, placeholders }] }`
- **数据源**：`server.js` 中的 `BUILTIN_CERT_TEMPLATES`（运行时动态生成，不依赖 data.json）

### POST /api/certificates
创建证书定义。`templateId` 必须是 12 套模板之一。
- **请求**：`{ name, company, templateId, validityType, validityDays, prefix, startNumber, digits, design, ... }`
- **字段说明**：
  - `company` — **企业名称**，默认值为 `广州游雁网络科技有限公司`，管理员可在新建/编辑弹窗中修改；证书底部落款、印章文字均从此字段读取。
- **校验**：`templateId` 必须匹配 `^[vh]\d$` 正则
- **响应**：`{ success: true, data: certificate }`

### （已删除）POST /api/certificates/preview / preview-html
> ⚠️ **2026-07-17 起已删除**。旧版用 Playwright 服务端无头 Chromium 渲染 PNG，存在字体偏移（Linux 无 Windows 专属字体）和服务器卡死问题。改为**前端浏览器内渲染**（见下「所见即所得」），这两个端点已移除，调用方会收到 404。

### 证书预览（前端渲染）
管理后台编辑器不再请求服务端，而是直接用 `html-to-image` 在浏览器内把 `renderDesignPageInner` 生成的 DOM 截成 PNG：
- 入口：`js/certificate-management.js` 的 `renderCertPreviewPng()`，调用 `htmlToImage.toPng(node, { pixelRatio: 3, cacheBust: true, skipFonts: true, backgroundColor: '#ffffff' })`。
- 字体统一：Windows 专属字体（STSong/SimSun→Noto Serif SC；STKaiti/KaiTi→Ma Shan Zheng；STFangsong/FangSong→Noto Serif SC；Microsoft YaHei/PingFang→Noto Sans SC）经 `mapCertFont()` 映射为 Google Fonts Web 字体，跨环境一致。
- 依赖：各页面 head 引入 `html-to-image@1.11.11` CDN + Google Fonts（Noto Serif SC / Noto Sans SC / Ma Shan Zheng）。

### GET /api/certificates
证书定义列表。`template` 字段通过 `getBuiltinTemplate(templateId)` 动态从 12 套模板元数据中查出。

### POST /api/certificates/:id/issue
颁发证书。流程：
1. `issueCertificateInternal` 写入 user_certificates 记录（`imageUrl` 初始留空）
2. 写通知消息
3. 学员端（个人中心 / 消息中心）**首次打开**证书时，若 `imageUrl` 为空，由浏览器内 `html-to-image` 渲染一次，并自动 `POST /api/user-certificates/:id/image` 上传落盘；之后 `imageUrl` 常驻有效，再次打开直接读取服务端 PNG，**不再重复渲染**（解决数据量大时每次打开都重渲染的性能问题）。

### POST /api/user-certificates/:id/image
接收前端（浏览器内 html-to-image）渲染出的证书 PNG（base64 dataURL），落盘到 `uploads/certificates/{userCertId}.png`，并把 `imageUrl` 写回 `data.json`。实现"首次渲染一次 → 永久保存至项目文件"。
- 请求体：`{ "dataUrl": "data:image/png;base64,...." }`
- 响应：`{ "success": true, "data": { "imageUrl": "/uploads/certificates/{id}.png" } }`

### GET /api/user-certificates
查询用户证书。`imageUrl` 首次渲染后由前端回传落盘并常驻有效；前端优先直接展示该图片，缺失时才客户端渲染。

## 关键设计决策

### 为什么删除旧 4 套 CSS 渐变模板？
旧 4 套（紫色/金色/绿色）通过 CSS 渐变模拟背景，**不真实**——文字叠加、印章位置、版式都偏离预期。改用 12 套真实 PNG 模板后，每个模板的版式（标题位置、副标题位置、姓名位置等）都是真实印刷品的留白，文字叠加位置准确。

### 为什么现在真正所见即所得？
- 管理后台编辑器预览、学员端展示**全部走同一套前端逻辑**：都用 `renderDesignPageInner` 生成 DOM，再用 `html-to-image` 截成 PNG。
- 彻底移除了服务端 Playwright 渲染（`certRenderDesignPageInner` / `renderDesignToPngBuffer` / `generateCertificateImage` 已删除），不再存在"编辑器画一套、服务端重渲染一套"的双管线差异。
- 字体经 `mapCertFont()` 统一映射为 Web 字体，Windows / Linux / 浏览器之间渲染完全一致，**根治字体偏移**。
- 无 Playwright 启动开销，**不再卡死**。

## 文件清单

### 前端
- `js/certificate-management.js` — 证书管理主模块（含 CERT_TEMPLATES 12 套定义、可视化编辑器、模板选择器、用户证书打印）
- `dashboard.html` — 管理后台布局 + 证书管理抽屉
- `center.html` — 个人中心"我的证书"列表（通过 `userCert.imageUrl` 展示 PNG）
- `messages.html` — 消息中心"证书通知"（通过 `dataUrl` 展示 PNG 缩略图）

### 后端
- `server.js` — 证书 REST API、`BUILTIN_CERT_TEMPLATES`、`ensureCertificateImage()`（严格校验磁盘图片存在才返回 URL）、`POST /api/user-certificates/:id/image`（接收前端 PNG 落盘）、`issueCertificateInternal`

### 资源
- `uploads/cert-templates/cert-v1.png` ~ `cert-h6.png` — 12 套真实证书模板（**唯一素材源**）
- `uploads/certificates/${userCertId}.png` — 学员端**首次打开证书时由前端渲染并自动落盘**生成；之后常驻有效，学员端优先读取，不再重复渲染。随证书记录删除而自动清理。

### 数据
- `data.json`:
  - `certificates` — 证书定义（含 `design`、`company` 字段）
  - `user_certificates` — 学员证书实例（含 `imageUrl`、`company` 字段）
  - ~~`certificate_templates`~~ — **已废弃**（旧 4 套模板已清空）

> **关于 `company` 与旧 `dept` 字段**：2026-07-21 起，证书定义原 `dept`（所属部门）字段统一改为 `company`（企业名称），默认值 `广州游雁网络科技有限公司`。`user_certificates` 原 `userDepartment` 也改为 `company`，颁发时从证书定义的 `company` 复制，不再取用户个人资料里的 `department`。已落盘 PNG 图片的证书保持原图不变（锁定图片），管理员后续修改证书定义的企业名称只影响新颁发/重新渲染的证书。

## 维护注意事项

1. **修改模板元数据时**：必须同步前端 `CERT_TEMPLATES` 和后端 `BUILTIN_CERT_TEMPLATES`，否则渲染结果会不一致。

2. **新增/替换模板时**：上传 PNG 到 `uploads/cert-templates/cert-{key}.png`（v1-v6 竖版尺寸建议 1425x2064，h1-h6 横版建议 2598x1795），同时更新两个常量。

3. **删除证书自动清理图片**：删除证书定义时（DELETE /api/certificates/:id）会级联删除关联 user_certificates 记录，并经 `tryDeleteUploadFile(uc.imageUrl, …)` **自动清理 `uploads/certificates/` 下对应的 PNG 文件**，无需手动处理。

4. **客户端渲染失败兜底**：若 `html-to-image` 未加载，`renderCertPreviewPng()` 会提示"预览组件未加载，请刷新"；学员端 `center.html` / `messages.html` 内也有 `generateCertificateImage()` 本地兜底函数。
